# راه‌اندازی سریع — ربات @ShirazMelk10bot

فایل `.env` همین پوشه با توکن این ربات پر شده است. **این پوشه/زیپ را برای کسی نفرستید** (توکن داخل آن است؛ هر کس توکن را داشته باشد ربات را کنترل می‌کند). بعد از تحویل، در @BotFather با `/revoke` توکن تازه بگیرید و فقط در `.env` سرور بگذارید.

فقط یک مقدار باقی مانده است (شناسهٔ مالک از قبل گذاشته شده: 792870828):

1. `LLM_API_KEY` ← کلید سرویس مدل زبانی (ایران: اگر مستقیم وصل نمی‌شود `LLM_BASE_URL` رله را هم بگذارید).

مراحل:
```
pip install -r requirements.txt
python selfcheck.py      # باید پنج ✅ بدهد (توکن، مالک، کلید، تلگرام، مدل)
python -m app.main       # اجرا؛ بعد در تلگرام به @ShirazMelk10bot بنویسید /start
```
`selfcheck.py` اعتبار توکن و اتصال به تلگرام و مدل زبانی را همان‌جا امتحان می‌کند. اگر «Unauthorized» داد، توکن را دوباره از BotFather کپی کنید.
ربات تا وقتی `python -m app.main` (یا Docker) روشن است جواب می‌دهد؛ برای همیشه روی یک VPS خارج از ایران اجرا کنید.

## چه چیزی تست شده و چه چیزی نه
- ✅ ۲۹ تست خودکار پاس شد (شامل CRM، تقویم، فایل/Revit، دفترها).
- ✅ اجرای کامل ربات روی تلگرام و مدل زبانی ساختگی: `/start` مالک، `/ledger`، `/tasks`، `/report daily`، پیام عادی، `/killswitch` و `/resume`، `/staff_add`؛ غریبه (ثبت‌نشده) پاسخ نگرفت؛ غیرمالک نتوانست دستور مالک بزند؛ پس از ثبت، همان کاربر پاسخ گرفت.
- ❌ با تلگرام واقعی و کلید واقعی مدل زبانی تست نشد (سرور من به api.telegram.org دسترسی ندارد و کلید مدل را ندارم). این را با `selfcheck.py` روی سرور خودتان ببینید.

متن دستورالعمل (`prompt/system_prompt_fa.txt`) ۱۲ جا به «پرسشنامه، ش. N» ارجاع می‌دهد. مقدارشان را فقط خود مالک می‌تواند بدهد (حدس نمی‌زنم): ش. ۶ (فرهنگ ارتباطی کارکنان)، ۷ (شاخص‌های ارزیابی کارکنان)، ۹ (سقف پرداخت مجاز)، ۱۰ (تعهدات مالی مهم)، ۱۱ و ۱۶ (بودجه/محتوای تبلیغات)، «فهرست مصوب اضطراری»، ۳۰ (قالب گزارش‌ها)، ۳ (سقف پروژهٔ هم‌زمان ← `WIP_CAP`). تا آن موقع ربات برای این موارد از مالک تأیید می‌گیرد.

# دستیار هوشمند مدیریتی — راه‌اندازی

یک ایجنت تلگرامی که دستورالعمل «پروفایل و انتظارات مالک» را اجرا می‌کند: وظیفه و پیگیری، دفتر تصمیم، کنترل پروژهٔ هم‌زمان، گزارش خودکار، درخواست تأیید، و **دفتر فعال‌سازی** که همه‌چیز را پیش‌فرض غیرفعال نگه می‌دارد.

## چه چیزی الان کار می‌کند (و تست شده)
| قابلیت | وضعیت |
|---|---|
| گفتگو با مالک/مدیران/کارکنان در تلگرام با نقش‌های جدا (فقط افراد ثبت‌شده) | کامل |
| وظایف: ایجاد، ابلاغ به مسئول در تلگرام، مهلت، معیار تکمیل، پیگیری سه‌مرحله‌ای (یادآوری ← پیگیری دوم ← گزارش تأخیر به مالک) | کامل |
| پروژه‌ها و سقف پروژهٔ هم‌زمان: بیش از سقف ← بلاک و درخواست تأیید مالک | کامل |
| دفتر تصمیم، یادداشت/درس‌آموخته | کامل |
| درخواست تأیید با دکمهٔ ✅/❌ برای مالک؛ اقدام‌های ممنوع سند همان لحظه رد می‌شوند | کامل |
| گزارش روزانه/هفتگی/ماهانه (تاریخ شمسی) از دادهٔ ثبت‌شده؛ چیزی که داده ندارد صراحتاً «متصل نیست» نوشته می‌شود | کامل |
| دفتر فعال‌سازی (سطح ۰ تا ۳ برای ۱۵ سامانه، با سقف هر سامانه طبق سند، مثلاً بانک فقط ۱) | کامل |
| kill switch: `/killswitch` همه چیز را صفر و دستیار را متوقف می‌کند | کامل |
| ثبت سوابق (audit) غیرقابل ویرایش/حذف؛ هیچ ابزاری برای حذف سوابق وجود ندارد | کامل |

## ماژول‌های داخلی (نسخهٔ نهایی؛ بدون هیچ حساب بیرونی کار می‌کنند)
بعد از اولین پیام، مالک یک بار بنویسد `/activate_internal` تا این‌ها روشن شوند (هرکدام جداگانه با `/revoke <system>` خاموش می‌شود):
| ماژول | چه می‌کند |
|---|---|
| CRM داخلی (`crm`) | مشتری/سرنخ/معامله با وضعیت، ارزش، تاریخ پیگیری؛ ثبت تماس و جلسه؛ یادآوری تلگرامی خودکار در موعد پیگیری؛ قیف فروش در گزارش هفتگی؛ جلوگیری از رکورد تکراری؛ حذف‌ناپذیر |
| تقویم و یادآوری (`calendar`) | جلسه/رویداد با یادآوری N دقیقه قبل در تلگرام؛ هشدار تداخل؛ `/agenda` |
| پرونده‌های پروژه و Revit (`project_files`, `revit_pm`) | هر فایلی که کارکنان در تلگرام بفرستند (تا ۲۰ مگابایت) ذخیره و فهرست می‌شود (`/files`)؛ جدول کمیت/متره Revit به صورت CSV یا Excel خوانده و خلاصه می‌شود (سرستون‌ها، تعداد ردیف، جمع ستون‌های عددی)؛ PDF متنی خوانده می‌شود؛ فایل rvt/dwg/ifc فقط نگهداری می‌شود (برای خواندنش از Revit خروجی جدول بگیرید) |
| دفتر مالی دستی (`finance_data`، فقط مالک) | ثبت درآمد/هزینه/مطالبه/بدهی به تومان با پروژه؛ خلاصهٔ سود خالص و مطالبات باز؛ در گزارش ماهانه می‌آید با برچسب «دفتر دستی، نه حسابداری رسمی» |
| کارکنان (`hr_data`، فقط مالک) | یادداشت عملکرد + آمار انجام وظایف هر نفر؛ تصمیم استخدام/حقوق با دستیار نیست |
| قراردادها (`contracts_docs`، فقط مالک) | دفتر قراردادها با طرف، مبلغ، پایان؛ هشدار قراردادهای رو‌به‌پایان در گزارش؛ امضا/نهایی‌سازی نمی‌کند |

دستورهای تلگرام: `/agenda` `/files` `/crm` (پیگیری‌های سررسید) `/activate_internal`؛ بقیه را با جملهٔ فارسی بگویید («سرنخ جدید: آقای رضایی ۰۹۱۲… ۵۰۰ میلیون، پیگیری فردا»، «جلسه با کارفرما پنجشنبه ۱۰ صبح»، «هزینه ۳۰ میلیون خرید مصالح ویلا»).
محدودیت صادقانه: داده‌ها فقط همان‌هاست که شما یا فایل‌های ارسالی وارد می‌کنند؛ این‌ها جایگزین حسابداری رسمی، Google Calendar یا نرم‌افزار Revit نیستند.

## چه چیزی عمداً وصل نیست (به حساب/دسترسی خود شرکت نیاز دارد)
واتساپ Business، اینستاگرام و تبلیغات، پیامک، پنل وردپرس، حسابداری هلو، بانک، Google Calendar: **گیت امنیتی و سطح دسترسی‌شان آماده است ولی اتصالشان پیاده‌سازی نشده** (هر کدام اکانت/API رسمی می‌خواهد). پرداخت، امضا و ارسال به مشتری اصلاً ابزار ندارند. اطلاعات بانکی فقط تا سطح «مشاهده» قابل فعال‌سازی است.

## راه‌اندازی
۱. در تلگرام از @BotFather یک ربات بسازید و توکن را بگیرید. شناسهٔ عددی مالک را از @userinfobot بگیرید.
۲. `cp .env.example .env` و مقادیر را پر کنید (`LLM_API_KEY`، `LLM_MODEL`، توکن، شناسهٔ مالک).
۳. اجرا با Docker:
```
docker build -t mgmt-agent .
docker run -d --restart=always --env-file .env -v $PWD/data:/srv/data --name agent mgmt-agent
```
یا بدون Docker: `pip install -r requirements.txt && python -m app.main`
۴. به ربات پیام بدهید. اولین کاربر همان مالکِ تعریف‌شده در `.env` است.

**ایران:** سرور باید هم به `api.telegram.org` و هم به سرویس مدل زبانی دسترسی داشته باشد. معمولاً یک VPS خارج از ایران ساده‌ترین راه است؛ در غیر این صورت `TELEGRAM_PROXY` و `LLM_BASE_URL` (رله) را تنظیم کنید. پایداری این مسیرها را از روز اول آزمایش کنید.

## دستورهای مالک
| دستور | کار |
|---|---|
| `/staff_add <شناسه> <manager\|staff> نام` | ثبت مدیر یا کارمند (فقط ثبت‌شده‌ها با ربات کار می‌کنند) |
| `/staff_off <شناسه>` | غیرفعال‌کردن (سوابق می‌ماند) |
| `/ledger` | وضعیت دفتر فعال‌سازی |
| `/activate <سامانه> <۰-۳> [محدودیت]` | فعال‌سازی صریح |
| `/revoke <سامانه>` | لغو یک مجوز |
| `/killswitch` / `/resume` | قطع کامل / ازسرگیری (دسترسی‌ها صفر می‌مانند) |
| `/report [daily\|weekly\|monthly]` | گزارش فوری |
| `/tasks` | وظایف باز |

بقیهٔ کارها (ایجاد وظیفه، پروژه، ثبت تصمیم…) را مستقیم به زبان فارسی بنویسید.

## تنظیمات مهم
- `WIP_CAP`: سقف پروژهٔ هم‌زمان (پرسشنامه ش. ۳). تا تعیین نشود (۰)، هر پروژهٔ تازه از مالک تأیید می‌گیرد.
- ساعت گزارش‌ها و روز گزارش هفتگی در `.env`.
- متن دستورالعمل: `prompt/system_prompt_fa.txt`. جاهای «(پرسشنامه، ش. N)» را بعد از گرفتن پاسخ مالک با مقدار واقعی پر کنید (سقف پرداخت، بودجه تبلیغات، فهرست اضطراری و…).

## امنیت و حریم
- فقط شناسه‌های ثبت‌شده پاسخ می‌گیرند؛ بقیه بی‌صدا نادیده و ثبت می‌شوند.
- متن پیام‌ها دستور نیست: هیچ پیامی سطح دسترسی را بالا نمی‌برد، فقط `/activate` مالک.
- متن پیام‌ها و داده‌هایی که ایجنت می‌خواند برای پردازش به سرویس مدل زبانی ارسال می‌شود. مالک باید این را صریحاً بپذیرد (پرسشنامه ش. ۲۷). شماره‌حساب، رمز و کد بانکی هرگز در تلگرام نوشته نشود.
- از پایگاه داده (`data/agent.db`) پشتیبان منظم بگیرید.
- `.env` را هرگز در مخزن یا پیام ارسال نکنید.
